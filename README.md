# Royal Catering — Лабораторная работа №4

Веб-приложение для заказа услуг выездного ресторанного обслуживания и кейтеринга (банкеты, фуршеты, выездные повара, официанты, мобильный бар, аренда посуды).

## Структура проекта (согласно шаблону курса)

- **`my-api/`** — серверная часть:
  - `backend/server.js` — сервер Express API с поддержкой PostgreSQL (`clinic_db`) и локальной резервной базы SQLite (`restaurant.db`).
  - `backend/database.sql` — SQL-скрипт структуры таблиц и начальных данных.
  - `backend/db.js` — модуль SQLite синхронизации.
  - `src/` и `vite.config.js` — веб-интерфейс мониторинга API.
- **`my-app/`** — клиентское веб-приложение React (Vite):
  - Каталог услуг с фильтрацией по категориям, ценам и поиску.
  - Карточки услуг с рейтингом и отзывами (все данные подтягиваются строго через SQL JOIN).
  - Модальное окно просмотра и добавления отзывов (оценка 1–5 звезд + комментарий).
  - Серверная корзина покупок (сохраняется в базе данных, уникальна для каждого пользователя).
  - Оформление заказа с валидацией даты доставки (не ранее текущей даты) и адреса.
  - Промокод `VIP10` со скидкой 10%.
  - Личный кабинет: просмотр всех сделанных заказов (каждый заказ отображается единым блоком с составом услуг без ID), редактирование профиля и смена пароля.
  - Авторизация, регистрация и восстановление пароля при утере ("проверка на глупого пользователя").
  - Панель администратора: полное управление услугами (CRUD), категориями (CRUD), смена статусов заказов, модерация отзывов и управление пользователями.
  - Переключатель темной и светлой темы.

## Быстрый запуск

### 1. Запуск Backend сервера
```bash
cd my-api/backend
npm start
```
Сервер запустится на порту `http://localhost:3100`. Подключается к PostgreSQL (`clinic_db`) или использует резервную базу SQLite (`restaurant.db`).

### 2. Запуск клиентского приложения
```bash
cd my-app
npm run dev
```
Откройте браузер по адресу: `http://localhost:5173`.

### 3. Запуск монитора API (опционально)
```bash
cd my-api
npm run dev
```
Откроется на `http://localhost:5174`.

## Соответствие требованиям Лабораторной работы №4

1. **Каталог услуг (2.1):** получение через API, отображение названия, описания, длительности, цены, категории и отзывов. Фильтрация по категориям и цене. Все связи подтягиваются **только через SQL JOIN**.
2. **Корзина (2.2):** сохраняется на сервере в базе данных (`cart_items`), сохраняется при выходе, уникальна для каждого пользователя.
3. **Оформление заказа (2.3):** валидация обязательного адреса и даты доставки (`дата >= текущая дата`).
4. **Авторизация и регистрация (2.4, 2.5):** валидация обязательных полей, regex для email, восстановление пароля по коду.
5. **Отзывы (2.6):** просмотр отзывов всеми посетителями, отправка отзывов авторизованными клиентами (оценка 1-5 звезд).
6. **Личный кабинет (2.7):** заказы сгруппированы в единый блок на каждый заказ, редактирование контактных данных и смена пароля через API.
7. **Обработка ошибок (2.8):** спиннеры загрузки, при отключении сервера выводится «Сервер выключен».
8. **Роли (3.9):** 2 роли (`admin` и `user`). Администратор имеет права добавлять, изменять и удалять услуги, категории, заказы, отзывы и пользователей.
